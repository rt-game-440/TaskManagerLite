## Issue #75 创建转储文件：验收

自动验证：`cargo test -p tml-core dump --lib`（对自己启动的子进程写最小转储并核对文件、PID 4 / 本程序拒绝、目标目录不存在时失败且不留文件、完整转储体积估算）；`cargo test -p tml-app dump`（默认文件名 `<进程名>.<PID>.dmp`、体积估算向上取整 MB）；`pwsh scripts/test-dump.ps1`（`--menu-action dump-mini|dump-full:<pid>` 钩子，用环境变量 `TML_DUMP_PATH` 指定输出路径不弹保存对话框：最小 / 完整转储写出文件、文件头 `MDMP`、完整大于最小、PID 4 被拒绝、32 位进程被拒绝、坏路径失败，三种失败都不留文件，日志只记 PID、类型、结果与错误码）。

设计要点（验收时对照）：

- 右键进程 →“创建转储文件”→“最小转储…”“完整转储…”；PID 0 / 4 与本程序自身置灰（标题写明原因），32 位目标进程（本程序是 64 位）置灰并写明位数不匹配，没有权限的进程置灰并写明“没有权限”。
- 保存对话框和写转储都在后台线程，界面不卡；写入期间状态栏显示“正在创建 … 的转储…”。默认保存位置是用户临时目录，文件名 `<进程名>.<PID>.dmp`。
- 完整转储先弹确认框，显示估算体积（进程私有内存）；写完弹出提示，主按钮“打开所在文件夹”（资源管理器中选中该文件）。
- 失败（含磁盘空间不足）会删除不完整的文件；取消保存对话框什么都不留。

以下只留下自动测试覆盖不到的观感与第三方工具行为（4 级，等回到电脑前）：

  - 预期：两个文件都能打开并看到线程与模块；完整转储可以看到内存内容；完整转储的确认框里的估算体积与实际文件大小同量级。
  - 用户反馈：

- [ ] 2. 受保护进程的失败提示（4 级）
  - 操作：右键 csrss.exe、MsMpEng.exe 等受保护进程，查看菜单项；以普通权限强行触发（如能点击）。
  - 预期：菜单项置灰并写明原因，或状态栏给出清晰的失败原因；保存位置里没有遗留的空文件。
  - 用户反馈：

## Issue #76 进程签名状态列：验收

自动验证：`cargo test -p tml-core signature --lib`（svchost.exe 靠目录签名为已验证且签名者含 Microsoft、无签名文件、不存在的文件、结果槽位只写一次）；`cargo test -p tml-app details`（签名只排队一次、各状态文字）；`pwsh scripts/test-signature.ps1`（设置里只显示“签名”列；环境变量 `TML_SIGNATURE_DUMP` 让每次签名结果刷新写出“PID、结果、签名者”：svchost.exe 已验证且签名者含 Microsoft、自己编译的 exe 为未签名、约 500 个进程在数秒内完成校验）。

设计要点（验收时对照）：

- “详细信息”可选列“签名”（默认不显示）：已验证 · 签名者 / 未签名 / 校验失败；还没校验完显示“…”，读不到映像路径的进程留空。点表头可排序（未签名 < 校验失败 < 已验证）。
- 离线校验：不做吊销检查（`WTD_REVOKE_NONE`、`WTD_CACHE_ONLY_URL_RETRIEVAL`），先验内嵌签名，没有则按文件哈希查系统目录签名（`CryptCATAdmin*`）。
- 单个最低优先级后台线程串行校验，同一路径只校验一次（进程存续期间的缓存按路径，不按修改时间）；列没显示就不校验。
- 局限：路径缓存只在本程序运行期内有效，文件在进程运行期间被替换不会重新校验（重新打开本程序即可）；校验失败不区分原因（改动、证书不受信任、读不到文件）。

以下只留下自动测试覆盖不到的项目（4 级，等回到电脑前）：

- [ ] 1. 断网时不卡界面
  - 操作：断开网络（或开飞行模式），在列选择器里勾选“签名”，同时滚动进程列表、切页。
  - 预期：界面始终流畅；“…”在几秒内逐步变成结果。
  - 用户反馈：

- [ ] 2. 第三方签名与观感
  - 操作：勾选“签名”列，看浏览器、Office、驱动程序等的显示；点表头排序。
  - 预期：第三方软件显示正确的签名者，未签名的小工具显示“未签名”；排序符合预期；列宽可拖动。
  - 用户反馈：
